# 新手套接入说明（纹路/图案不同的手套）

本 demo 的检测链路对手套**颜色/纹路零假设**：框检测是 YOLO-World 文本提示
驱动（默认提示词 `["hand","glove"]`，零样本可换词），关键点是 RTMPose hand5
通用**手部**模型（认手的几何，不认手套外观），稳定层（HandTracker/OneEuro/
手性锁存/复活）纯几何。所以新手套大概率**零改动直接可用**——按下面顺序验证，
哪步不够再走哪步的升级路线。

## 一、2D 快筛（零成本，先做这步）

任意一段新手套视频（mp4）即可，不需要深度：

```bash
./tools/hand_3d_d435/run_live_d435.sh \
    --uvc /path/新手套.mp4 --glove --export /tmp/新手套_2d --stats --no-window
```

看结尾 `--stats` 诊断：
- **出框率**（手套模式: N 帧 | 出框 M 帧）：≈黑手套基线 76% 量级即框检测正常；
  明显偏低 → 分支 A。
- **检测手数**（0/1/2 手帧占比）：0 手帧多且出框率低 = 框漏检；出框率高但
  0 手多 = 框有、关键点解不出 → 分支 B。
- 想目视：去掉 `--no-window`，q/s/g 键同 3D 窗口。

## 二、3D 实测（D435）

**实时目视**（主程序未占用 D435 时）：

```bash
./tools/hand_3d_d435/run_live_d435.sh --glove
```

**拿数字**（与黑手套基线对照）：用主程序录一段新手套 D435 会话（含深度），
然后回放全链：

```bash
./tools/hand_3d_d435/run_live_d435.sh \
    --replay data/recordings/<会话名>/<会话名>_000001 --glove --stats --no-window
```

对照口径（黑手套基线，静止双手录制）：

| 指标 | 黑手套基线（000001 / 000003） | 新手套 |
|---|---|---|
| 2 手帧占比 | 75.3% | |
| 出框率 | 76.1% | |
| 同 label 帧（两手混淆） | 4 帧 | |
| 静止质心跳 renderer_in p95 | 10.9-13.5mm | |
| wholesale 起数 | 2-3 起 | |

（裸手基线 222_000011：2 手 94.9%、12.6mm——手套遮挡天然低于裸手，
不要拿裸手数字当目标。）

## 三、分支 A：框漏检（出框率低）

1. **换提示词试跑**（无需训练）：
   ```bash
   ./venv/bin/python glove_package/world_detector.py \
       --weights glove_package/yolov8m-worldv2.pt \
       --prompt hand glove "textured glove" --max-boxes 2
   ```
   纹路款可试的词：`glove`、`textured glove`、`patterned glove`、
   颜色/材质描述（如 `black glove`）……找到出框稳的词后：
   - 短期验证：改 `hand_3d_d435/glove_detector.py:76` 的
     `_WORLD_PROMPT = ["hand", "glove"]` 一行即可；
   - （如经常换词，再加 `--glove-prompt` 命令行参数——当前未暴露。）
2. **仍不行 → 训练自己的框检测器**（约半天，配方完整在
   `glove_package/使用说明.md` 第三节）：
   ```bash
   cd glove_package        # 工具必须 cwd 在包内
   ../venv/bin/python hand_demo_mmpose.py --prompt glove   # 按 r 采集 200+ 帧
   ../venv/bin/python prepare_dataset.py --captures captures1 --out dataset
   ../venv/bin/python auto_label.py --dir to_label        # 零样本预标漏检帧
   ../venv/bin/python annotate.py --dir to_label          # 人工复核
   ../venv/bin/python prepare_dataset.py --merge to_label --out dataset
   ../venv/bin/python train_detector.py --data dataset/data.yaml --epochs 100 \
       --no-augment-hsv
   ```
   训练产物 `glove_package/runs/hand_det/weights/best.pt`，接到 demo：
   ```bash
   ./tools/hand_3d_d435/run_live_d435.sh --glove \
       --glove-weights glove_package/runs/hand_det/weights/best.pt ...
   ```
   （权重名不含 "world" 会自动走 YOLO 后端，conf 默认 0.3；可用
   `--glove-det-conf` 调。）
   注意：`prepare_dataset.py` 重跑会覆盖人工重标——复核完的标注先合并
   落库，不要反复重跑 prepare。

## 四、分支 B：框有、关键点飘/漏点

1. 量化现状（对采集帧跑关键点质量验证）：
   ```bash
   cd glove_package && ../venv/bin/python verify_pose.py --dir to_label
   ```
2. 已知事实（黑手套实测）：裁剪 MediaPipe 对戴手套是死路；RTMPose hand5
   对近手/非掌心正对姿态本来就弱——**渲染稳≠检测好**，稳主要来自
   HandTracker + OneEuro 稳定层，不是检测器本身。
3. 纹路干扰 keypoint 时正路 = 用新手套数据微调关键点模型（大工程，仅确需
   时做；配方：ultralytics pose 标签 68 token、vis 1/2 进损失、
   yolo11n-pose 从框模型迁移）。到这一步再议。

## 五、坑

- `--uvc` 吃 mp4 是 **2D-only**（无深度 → 无 3D 关键点/深度图；--export
  只产 keypoints_2d.parquet + rgb_overlay.mp4）。要 3D 必须走 D435 实时或
  录制会话回放。
- D435 被主程序占用时 demo 打不开（EBUSY），先关主程序的 D435 预览。
- 手套会话目录名格式：`data/recordings/<名字>/<名字>_000001/`（视频在
  `videos/d435_rgb/chunk-0000/`）。
- 实机目视切换手套模式：demo 运行中按 `g`。

## 六、新手套实测记录（2026-08-21，纹路款，Project_Test10_000004）

3D 全链回放（`--replay Project_Test10_000004 --glove --stats --no-window
--export`，477 帧）：**零改动直接可用**，多数指标优于黑手套基线：

| 指标 | 黑手套基线 | 新手套 000004 |
|---|---|---|
| 2 手帧占比 | 75.3% | **85.3%** |
| 0 手帧占比 | 23.5% | **4.2%** |
| 出框率 | 76.1% | **99.6%** |
| 静止质心跳 renderer_in p95 | 10.9-13.5mm | **8.7mm** |
| 两手同 label（几何兜底前） | 4 帧 | 54 帧（f137-216 窗口集中，几何兜底后导出 0 帧） |
| wholesale | 2-3 起 | 17 起（f137-216 身份换手瞬态，两帧确认机制挡下） |

结论：纹路手套对 YOLO-World 零样本提示词反而更好认（出框 99.6%）。唯一
偏弱的是 f137-216 段的身份混淆（两手同 label → 几何兜底+wholesale 双保险
扛住，最终导出数据干净）。若日后该段抖动影响观感：先试调 `--glove-det-conf`
（更低→出框更全）或该段拍摄时避免两手快速交叉/对称姿态；要彻底治再上
关键点微调（分支 B）。

## 七、背面/侧视渲染优化（2026-08-21 已落地，默认生效）

问题：背面朝向相机时 RTMPose 逐点置信度塌陷（000004 实测 f160-219 均
0.29，正面 0.5-0.7），但骨架几何"看似合理"能通过退化三条件 → 抖动骨架
直通渲染。

方案（快速调优，未训练）：
1. **低置信 hold 门**（`--glove-pose-conf`，默认 0.3，0=关）：pose 逐点
   均值置信低于门的手，只持出上次输出（不喂 OneEuro 新点、不更新锁存、
   不计退化），置信恢复自动续上；无旧点可持的新 track 不 hold（保存在性）。
   hold 期间旧点回喂 OneEuro 保持滤波时间连续，恢复不跳变。
2. **--glove-lost-timeout**（默认 3）：双手交叉/重叠导致框频繁合并拆开、
   反复换 id 的会话（如 000004 f312-388 隔帧交替 0/1 手）可调 8——
   000004 实测 2 手 85.3%→88.3%、0 手 4.2%→1.7%；但单手频繁进出的会话
   （Test_Data_000003）调 8 会把静止段 p95 12.4→25.1mm 恶化，按会话取舍。
   另有 --glove-nms-iou / --glove-box-alpha / --glove-freeze-max 可调。

落地数字（000004 默认参数前后对比）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 2 手 / 0 手 | 85.3% / 4.2% | 85.3% / 4.2%（保持性不变） |
| f160-219 低置信帧被 hold | 0（直通渲染） | 30/60 |
| 同 label 帧 | 54 | 52 |
| wholesale | 17 起 | 17 起 |
| 静止段 renderer_in p95 | 8.7mm | 9.0mm |

黑手套回归：000001 无变化（2 手 75.3%）；000003 p95 12.4→11.7mm、
0 手 56.6→52.8%（微改善）；裸手 222_000011 94.9% 不变。
